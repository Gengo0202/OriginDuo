## 新增

- **状态栏性能读数：充电功率与电池温度**（默认都关，各自一个开关，都在「常规」页）。
  - **充电功率**取的是**电池自身**的电流 × 电压，也就是真正充进电池的功率，会随电量升高逐渐变小；
    刻意不取充电器协商出来的最大档位——那个数字在功率已经掉下来之后仍然不动。不足 10W 保留一位
    小数。**没接充电器时不显示这一段，而不是显示 0W**（0W 是一个读数，而没接充电器是「没有这个
    读数」）。
  - **电池温度**取整到整摄氏度。温度是电池自己的属性，不接充电器同样显示。
  - 两项共用同一处位置，且**一项占一行**：只开一项就只显示那一项，两项都开则上下两行显示。字号以
    「环外网络类型字号」为基准，两项都开时按电池图标的高度自适应缩小，让两行合起来不高于一个图标；
    空间实在太窄时会在基准字号的六成处封底，此时两行会略微高过图标一点，而不会缩到看不清。
- **「图标整体尺寸」（尺寸页，60 – 100%）**：整个三合一图标相对状态栏给定框的百分比，默认 100%。
  状态栏的框只有约 20dp 高，所以只能缩小、不能放大；100% 就是系统给多大画多大。缩小时描边、圆弧
  与文字按同一比例一起缩，形状不变。
- **「读数整体尺寸」（尺寸页，60 – 150%）**：两项读数在自适应大小之上的百分比，默认 100%。这是
  「自适应字号」之上的最后一次缩放，乘在**每一种**答案上，所以只开一项的读数也有可见效果。
- **「读数字重」（尺寸页，100 – 900，默认 700）**：两项读数文字的笔画粗细。它独立于「数字字重」与
  「网络类型字重」，改它不会连带把旁边的 5G 标签一起加粗。
- **圆环顶部缺口的占用顺序改为「双卡 → Wi-Fi 弧 → 环内网络类型」**：缺口只有一个位置，此前是各个
  占位者各自判断，会出现「双卡排让开了、Wi-Fi 弧也没画、缺口空着」这种谁都没占的情况。现在按上面
  的顺序仲裁，只有环内充电闪电能压过双卡排。锁定「充电时显示闪电」关掉时，闪电交还系统绘制，缺口
  也就重新腾给双卡排（此前是按「正在充电」判断的，插着电但闪电关掉时缺口会白白空着）。

## 修复

- **充电功率不再长期显示 `0.0W`**：此前把负的 `current_now` 当成「正在放电」折成了 0，而这台机器
  **充电时回的就是负数**——实测 USB 供电、状态 charging、`charge_counter` 同时在涨的情况下，连采
  8 次全是 `-115000 … -204000 µA`。于是每一个真实的充电电流都被判成 0，状态栏一直停在 `0.0W`，只有
  采样抖动恰好落在正值时才闪出一次真数。电流的正负号各家平台不一致，现在只取幅值；答不出来仍返回
  「未知」而不是 0，真零仍是真零。
- **读数旁边的原生图标不再频繁横移**：功率大约每秒更新一次，此前每一次更新都会让电池旁预留的宽度
  重新算一遍，MIUI 的整排原生图标就跟着左右滑一下（用户报告「功率数字的变化会导致左侧图标位置
  跳动」）。根因在拆卸路径：`removeOutTypeLabel` / `removePerfLabel` 的第一步都是先把预留交还，
  **排在「到底有没有挂东西」的判断之前**，而这两个方法每次同步都会跑（环外网络类型默认关闭，
  「根本没有标签」是常态路径），视图为空时直接返回、不再重新预留——于是图标行的 padding 每轮
  `107 → 0 → 107` 地乒乓，整排图标横移 107px 再弹回。现在两个方法只负责移除自己那一个视图，预留
  宽度交给唯一的权威去算，它按实际在屏的视图求和、总和为零时自己交还。

## 优化

- **精简了设置页的描述文字**：「常规」页与「尺寸」页每一行的说明都压缩到一两句，去掉了重复解释
  开启方式与显而易见的后果的部分，把「为什么这样设计」这类内容留在文档里。
- 「读数整体尺寸」与新增的「读数字重」放在「尺寸」页的**整体尺寸**小节，与「图标整体尺寸」相邻——
  它们和描边粗细、字号是一类东西（都是数字），而一页开关不是滑杆该待的地方。

## 说明

- 两项读数**默认关闭**，什么都不开时状态栏与之前完全一致。
- **真机已验证**：功率读数在插着充电器时显示真实瓦数（`1.3W` / `0.6W` / `4.52 KB/s` 旁），不再停在
  `0.0W`；连续 14 帧截图里左侧原生图标钉死在同一位置，而同一个窗口内读数文本在 5 个值之间变化。
- **回归验证**：九条断言脚本全部通过（含 `perf-layout` 76 条、`battery-presence` 44 条、
  `glyph-scale` 17 条），其中两条新加的源码契约专门锁住上面那个「抢先交还」的写法，防止它被改回来。
- **已知问题（与本模块无关）**：锁屏状态栏里的耳机与辅助电池图标不跟随反色。把模块整个关掉之后重启
  系统界面，这两个图标**依然是白的**，所以这不是本模块引起的行为；设备上该耳机电量图标由第三方模块
  `moe.chenxy.huaweipods` 绘制。若你也在用类似模块，可以往那个方向排查。
